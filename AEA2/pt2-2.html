Nextcloud: tu propio servicio de archivos

Pasamos de usar servicios ya preparados a instalar y administrar un espacio privado para el equipo de un evento.

Idea clave

Dos maneras de trabajar en la nube

Drive y Dropbox son servicios preparados: nos registramos y empezamos a guardar archivos. Nextcloud ofrece funciones parecidas, pero se instala y se administra en un servidor propio. Por eso, además de aprender a usarlo, aprenderás qué piezas hacen posible el servicio.

Cómo responde el servidor

Qué ocurre cuando abres Nextcloud

Al escribir una dirección como http://localhost/nextcloud, tu navegador envía una petición. El servidor la recibe, ejecuta la aplicación y devuelve una respuesta. Este recorrido es la base de cualquier aplicación web dinámica.

Apache

Es el servidor web. Escucha peticiones del navegador y entrega páginas, imágenes o archivos.

PHP

Es el lenguaje y entorno que ejecuta el código de Nextcloud. No es otro ordenador: trabaja dentro del servidor web.

MariaDB

Es la base de datos. Guarda cuentas, grupos, permisos, nombres de archivos y otra información de la aplicación.

Carpeta de datos

Es donde se guardan físicamente los carteles, documentos y demás archivos del evento.

Nextcloud combina estos componentes: PHP decide qué puede hacer cada persona; MariaDB aporta la información; la carpeta de datos conserva los archivos. Durante el asistente se crean automáticamente las tablas de MariaDB.

Antes de empezar

Qué sí es y qué no es

Como Drive o Dropbox

Sirve para colaborar con archivos, carpetas, enlaces, versiones y clientes de sincronización.

Con una diferencia

El servicio se instala en nuestro servidor. Por eso gestionamos cuentas, permisos, actualizaciones y espacio.

No es alojamiento web

Nextcloud no sustituye a Dotació.cat: la web HTML pública del evento se publicará en Pt2.3.

De práctica a servicio real

Esta práctica local no es un servicio publicado

No tienes que configurar nada de esta sección. Su objetivo es diferenciar el montaje de aula de un servicio que una organización mantiene para que otras personas lo usen de verdad.

Ahora: práctica en tu máquina

  • Entras desde localhost: solo desde tu propio Ubuntu.
  • Usas datos ficticios y cuentas de prueba.
  • HTTP es suficiente porque no sale de tu equipo ni de la actividad.
  • El objetivo es aprender cómo se relacionan Apache, PHP, MariaDB y Nextcloud.

Después: servicio para un equipo real

  • Otras personas podrían entrar desde la red o Internet.
  • Se guardarían archivos y cuentas que hay que proteger.
  • La persona administradora tendría que mantenerlo y recuperarlo ante un fallo.
  • El objetivo sería ofrecer un servicio fiable, no solo demostrar que funciona.

Cuatro medidas que harían falta en ese servicio real

HTTPS

Protege la comunicación entre el navegador y el servidor para que una contraseña no viaje visible por la red. En clase no hace falta porque trabajamos en local.

Dirección autorizada

Nextcloud guarda una lista de direcciones desde las que acepta abrirse, llamada dominio de confianza. Evita que se use con una dirección no prevista.

Copias de seguridad

Para poder recuperar el servicio no basta con copiar los archivos: hay que guardar la carpeta de datos, la base de datos y la configuración.

Cron

Es un programador de tareas: como una alarma que ejecuta mantenimiento periódico aunque nadie tenga abierta la web.

Para Pt2.2 basta con reconocer estas cuatro ideas y explicar para qué servirían. No debes instalar HTTPS, configurar un dominio, programar cron ni preparar copias de seguridad.
